# Node Executor Skill

- node_id: chapter_metadata_enrichment
- role: executor
- validator_id:

## 任务目标

对分段后的所有篇章文档进行元数据丰富处理。核心要求是为每个段落生成**真实、准确、有效**的译文和注释，并为每个篇章撰写**实质性**的解析内容。**严禁输出任何占位文本**，如"【译文】第 xx 段"、"译文待补充"、"解析内容"等模板性文字。

## 处理流程

### 1. 篇章类型识别

读取每个篇章内容，识别其体裁类型：诗、词、文、赋、论。

### 2. 创作年份提取

根据作者、内容线索和朝代信息估算或提取创作年份。若无法确定，填写朝代范围（如"唐代"）或留空（空字符串）。

### 3. 译文生成（核心任务）

**必须为每个段落生成真实的现代汉语白话文译文。**

要求：
- 译文必须是对原文内容的忠实翻译，不得是占位文本
- 译文应流畅、准确，保留原文意境
- 对于诗词，逐句翻译，保留意象
- 对于散文，按句意翻译，不逐字直译
- **严格禁止**：`【译文】第X段`、`译文：（待补充）`、`（译文）`、`此处为译文`等任何占位格式
- **严格禁止**：translation 字段与原文 content 完全相同（表示未翻译）
- **严格禁止**：translation 字段为空字符串（诗词类必须有译文）

示例（《道德经》第一章）：
- 原文：道可道，非常道；名可名，非常名。
- 译文：可以说得出来的道，就不是永恒不变的道；可以叫得出来的名，就不是永恒不变的名。

### 4. 注释识别

识别段落中的难词、古字、典故，生成注释。格式：`词语:解释,词语:解释`

若段落无需注释，填写空字符串。

### 5. 解析撰写（核心任务）

**必须为每个篇章撰写实质性的解析内容（不得为空，不得为占位文本）。**

要求：
- 内容涵盖：篇章主旨、艺术特色、历史背景、思想内涵等方面
- 长度：100-300 字之间
- 语言客观、学术性强，有实际分析价值
- **严格禁止**：空字符串、`（解析待补充）`、`此处为解析`等任何占位内容

## 输出格式

每个篇章输出一个 JSON 文件：

```json
{
  "chapter_id": "章节唯一标识",
  "chapter_title": "篇章标题",
  "chapter_type": "诗/词/文/赋/论",
  "year": "创作年份或朝代",
  "analysis": "实质性的篇章解析内容（100-300字，不得为空或占位）",
  "paragraphs": [
    {
      "seq": 1,
      "content": "原文段落内容",
      "translation": "真实的现代汉语译文（不得为占位文本）",
      "notes": "词语:解释,词语:解释"
    }
  ]
}
```

## 质量红线（validator 将拒绝通过）

1. 任何段落的 translation 字段包含"【译文】"、"第X段"、"占位"等模式
2. 任何篇章的 analysis 字段为空字符串或占位文本
3. translation 字段内容与原文 content 完全相同（未翻译）
